# 要件定義書

## 1. 背景・目的

- 背景: 自作のECパッケージを構築し、製品化を目指す。
- 目的: プロトタイプとなるサイトを、低い開発コストかつ高い品質で構築できる状態にする。

## 2. スコープ

### 対象

- EC基盤
- EC CMS
- EC統合管理画面

### 対象外

- サイト構築(個別のECサイトの構築作業)

## 3. 利用者・ステークホルダー

- ECサイトを構築したい企業と、その運用担当者
- プラットフォームを管理(運用・保守)する開発担当者(本人)
- 体制: 個人開発のため、関係者・承認者は本人のみ

## 4. 機能要件

3システムを同時に開発する。優先度はすべて「高」とする(細分化は未決事項を参照)。

### システム概要

| システム | 役割 |
|---|---|
| EC基盤 | EC CMS・EC統合管理画面と連携するコアシステム。ECサイトとして成立させる役割を持ち、カートなどEC必須機能も担う |
| EC CMS | テーマ、コンテンツ、コンポーネントを管理する |
| EC統合管理画面 | ECサイト全体の設定と、商品・在庫などの管理を一元的に行う |

### 機能一覧

| ID | 機能 | 概要 | 優先度 |
|---|---|---|---|
| F-01 | EC基盤: コア機能 | EC CMS・EC統合管理画面と連携し、ECサイトとして成立させる基盤 | 高 |
| F-02 | EC基盤: カート | カート機能などECに必須の機能を提供する | 高 |
| F-03 | EC CMS: テーマ管理 | テーマを管理・編集する | 高 |
| F-04 | EC CMS: コンテンツ管理 | 商品情報、記事媒体などのコンテンツを管理する | 高 |
| F-05 | EC CMS: コンポーネント管理 | コンポーネントを管理する。同じコンポーネントでUIを切り替えられる | 高 |
| F-06 | EC CMS: 標準・個社対応の切り分け | 標準仕様と個社対応を分けて管理する | 高 |
| F-07 | 管理画面: サイト全体設定 | 会社情報、画面一覧などサイト全体の設定 | 高 |
| F-08 | 管理画面: 商品管理 | 商品を管理する | 高 |
| F-09 | 管理画面: 在庫管理 | 在庫を管理する | 高 |
| F-10 | 管理画面: SEO・計測設定 | SEOルール、GA/GTMに必要な設定 | 高 |
| F-11 | 管理画面: コンポーネント選択 | 画面ごとに必要なコンポーネントをEC CMSから選択する | 高 |
| F-12 | 管理画面: テーマ選択 | テーマを選択する(管理・編集はEC CMS側) | 高 |
| F-13 | 決済連携(モック) | GMO決済をモックで連携する | 高 |

## 5. 非機能要件

| ID | 分類 | 項目 | 要件 | 備考 |
|---|---|---|---|---|
| N-01 | 性能 | 同時アクセス | 同時1,000アクセスに耐えられること | 表示速度の目標は未設定 |
| N-02 | セキュリティ | 個人情報の保護 | 個人情報はマスクをかける | |
| N-03 | セキュリティ | 同意取得 | ECサイトでの個人情報の取り扱いについて、利用者の同意を取る | |
| N-04 | セキュリティ | 認証 | ログイン認証はOAuthとする | |
| N-05 | セキュリティ | 権限 | 「クライアント」「システム管理者」「開発者」に分ける | サービスごとに異なる場合があるため、サービスごとに定義する(7章) |
| N-06 | 運用 | ダッシュボード | 案件ごとに用意する | |
| N-07 | 運用 | バックアップ | DBデータのバックアップを残す | 要設計(7章) |
| N-08 | 運用 | 監視 | SentryまたはMackerel等によるアラート監視を想定する | 採用サービスは未定 |
| N-09 | 運用 | マルチテナント | 別途検討する | 要否・方式は未定(7章) |

## 6. 制約・前提条件

- 期限: 3か月で作り切る。
- 費用: プロトタイプのため、ほぼ無料が望ましい。
- 開発体制: 個人開発。
- 決済: GMO決済(モック)。それ以外の外部サービスは一旦なし。
- 技術スタック: 未定。

## 7. 未決事項

決めるべきことを分野ごとにまとめる。「現状」は今わかっていること、「決める内容」は決着させたい論点。

### 技術・インフラ

3か月・ほぼ無料という制約(6章)があるため、技術スタックを最初に決め、インフラ・費用はそれに合わせて選ぶ。

| 項目 | 現状 | 決める内容 |
|---|---|---|
| 技術スタック | 未定 | 言語、フレームワーク、DB。3システムで共通にするか |
| サーバー | 未定 | ホスティング先。同時1,000アクセス(5章)を満たせる構成か |
| ドメイン管理 | 未定 | 取得先、管理方法、案件ごとのドメイン運用 |
| 費用 | プロトタイプのためほぼ無料が望ましい | 無料枠で収まる構成にできるか。超える場合の上限額 |

### 設計方針

| 項目 | 現状 | 決める内容 |
|---|---|---|
| マルチテナント | 別途検討 | 要否と方式(複数企業の利用をどう分離するか)。ダッシュボードが案件ごと(5章)である点と合わせて検討 |
| 権限定義 | クライアント、システム管理者、開発者の3区分。サービスごとに異なる可能性あり | サービス(EC基盤、EC CMS、EC統合管理画面)ごとの権限の中身 |
| DBバックアップ | DBデータを残す想定。要設計 | 頻度、保存先、保存期間、復旧手順 |

### 進め方

| 項目 | 現状 | 決める内容 |
|---|---|---|
| 機能の優先度 | 3システム同時開発のため、すべて「高」 | 3か月で作り切れない場合に、後回しにする機能の順位 |

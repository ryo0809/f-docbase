# f-docbase

要件定義書・設計書などのドキュメントを、画面上で作成・編集・管理できる個人用ドキュメントWebアプリ。
成果物はすべてWeb上で確認できる。

## 要件

| 項目 | 内容 |
|---|---|
| 目的 | 要件定義書・設計書などを画面上で作成・編集・管理し、Web上で閲覧する |
| 利用者 | ログインしたユーザー(オーナー / 開発メンバー / 一般メンバー。「認証と権限」を参照) |
| 実行環境 | まずローカルのみ。将来サーバーへ載せることを検討 |
| 編集 | Markdownを画面上で編集し、プレビューも表示する |
| 保存 | Markdownファイルをそのまま保存(DBなし)。リポジトリ内の `docs/` に置く |
| メタデータ | 各 `.md` 先頭のfrontmatter(YAML)にタイトル・タグ・更新日などを持つ |
| 履歴管理 | MVPでは不要 |

### MVP機能

- ドキュメントのCRUD(作成・閲覧・編集・削除・一覧)
- テンプレート(要件定義書・設計書の雛形から作成)
- フォルダ / タグによる整理

### Markdown表現

- Mermaid図
- 画像のアップロード / 貼り付け
- コードハイライト
- 目次の自動生成

### 対象外(将来検討)

- 全文検索
- 履歴管理 / 差分表示
- サーバーデプロイ

## 技術選定

| 領域 | 採用 |
|---|---|
| フレームワーク | Next.js(App Router)+ TypeScript |
| 保存層 | Node.js `fs` で `docs/` を直接読み書き、`gray-matter` でfrontmatter解析 |
| 編集UI | `<textarea>` + プレビューの2ペイン(プロトタイプ)。CodeMirror 6 への置き換えを想定 |
| 描画 | `react-markdown` + `remark-gfm` + `rehype-highlight` + `rehype-slug` + `mermaid` |
| 画像 | `docs/assets/` に保存し、相対パスで参照 |
| スタイル | Tailwind CSS |

## ディレクトリ構成

```
docs/                 ドキュメント本体(.md)。フォルダ階層がそのまま整理構造になる
  assets/             アップロード画像
templates/            ドキュメントのテンプレート(.md)
src/
  app/                画面とAPI Route
  components/         UIコンポーネント
  lib/                ファイル操作・frontmatter処理
```

## 認証と権限

ログインしないと、画面も API も使えない。ユーザーのロールによって、できる操作が決まる。

| ロール | 閲覧 | 編集(作成・更新・移動・画像アップロード) | 削除(ドキュメント・フォルダ) | ユーザー管理 |
|---|---|---|---|---|
| オーナー | ○ | ○ | ○ | ○ |
| 開発メンバー | ○ | ○ | ✕ | ✕ |
| 一般メンバー | ○ | ✕ | ✕ | ✕ |

- ユーザーの作成、ロールの設定、パスワードの変更は、オーナーが管理ページ(`/admin`)の「ユーザー管理」タブで行う。
- 最後のオーナーの削除・降格と、自分自身の削除・ロール変更はできない。
- パスワードは scrypt でハッシュ化して保存する。セッションは署名付き Cookie(7日間)。ロールは毎回ユーザー情報から読むため、変更や削除はすぐ反映される。
- ユーザー情報は `data/users.json`、セッションの署名キーは `data/session-secret`(いずれも Git 管理外)に保存する。署名キーは初回に自動生成される。

### パスワードを忘れたとき

- オーナー以外のユーザー: オーナーが管理ページの「ユーザー管理」タブで、パスワードを変更する。
- オーナー自身: サーバーのあるマシンで、次のコマンドを実行する(サーバーの再起動は不要)。

```
make reset-password USER_NAME=<ユーザー名>
```

  実行後にパスワードの入力を求められる(画面にもシェルの履歴にも残らない)。`make` が使えない環境では、`node scripts/reset-password.mjs <ユーザー名>` でも同じ。

### 初期設定

環境変数の設定は不要。ユーザーが1人もいない間は、ログイン画面に「初期設定」のフォームが表示される。ここで最初のユーザー(オーナー)を作成すると、そのままログインできる。2人目以降は、オーナーが管理ページの「ユーザー管理」タブで追加する。

- 初期設定のフォームは、最初にアクセスした人がオーナーになる。サーバーを公開する前に、自分で設定を済ませておく。
- 保存先を変えたい場合は、環境変数 `USERS_FILE`(ユーザー情報)、`SESSION_SECRET_FILE`(署名キーのファイル)で指定できる。署名キーを環境変数 `SESSION_SECRET`(16文字以上)で直接指定することもできる(任意)。

## 設計上の注意

- ファイル操作ではパスを正規化し、`docs/` 外へのアクセスを拒否する(パストラバーサル対策)。
- 保存先は環境変数 `DOCS_DIR` で切り替え可能(未指定時は `./docs`)。
- `fs` に依存するため、将来のデプロイはサーバーレスではなくDocker + VPS/自宅サーバー等が前提。公開時は HTTPS で配信する。`data/` はバックアップ対象に含める。

# create-design スキル

要件定義書・機能設計書(Markdown)を、ヒアリングしながら作成・更新するための Claude Code スキル。
作成したファイルは `docs/` に保存され、f-docbase のアプリ上でそのまま閲覧・編集できる。

## 使い方

Claude Code で次のように呼び出す。

```
/create-design
```

「要件定義書を作りたい」「機能設計書を作りたい」のように話しかけても起動する。

## 流れ

| # | ステップ | 内容 |
|---|---|---|
| 1 | モード選択 | `requirements`(要件定義書)か `functional-design`(機能設計書)。依頼文で明らかなら質問せずに進む |
| 2 | 保存先フォルダ | 既存フォルダから選ぶ。新規フォルダ名も入力できる |
| 3 | タイトル | ファイル名はタイトルから自動で決まる |
| 4 | 既存ファイルの確認 | 同名、または同じタイトルのファイルがあれば**更新**として進める |
| 5 | タグ | 既存タグから複数選択、新規タグも追加できる |
| 6 | ヒアリング | テンプレートの節に沿って1回に2節ずつ聞く(下記「モード」参照) |
| 7 | 作成・保存 | `docs/<フォルダ>/<ファイル名>.md` に書き込む |
| 8 | 報告 | 保存パス、アプリで確認できるURL、内容の要約、未決事項を報告 |

## モード

| モード | テンプレート | 節 |
|---|---|---|
| `requirements`(要件定義書) | `templates/requirements.md` | 1. 背景・目的 〜 7. 未決事項 |
| `functional-design`(機能設計書) | `templates/functional-design.md` | 1. 概要、2. 機能仕様、3. 画面設計、4. 処理フロー、5. データ設計、6. インターフェース、7. エラー処理・例外、8. 未決事項 |

機能設計書では、機能仕様を `FD-01` から採番し、関連する要件定義書の機能ID(F-xx)を概要に書く。処理フローは Mermaid の図で書け、アプリ上で描画される。

## 保存されるファイル

```
docs/<フォルダ>/<ファイル名>.md
```

- ファイル名はタイトルから決まる。`/ \ : * ? " < > | # %` は半角スペースに置き換わる。
- 先頭にfrontmatterが付く。

  ```yaml
  ---
  title: ECパッケージ(開発要件整理)
  tags:
    - ECパッケージ
  updated: '2026-10-05T00:00:00.000Z'
  ---
  ```

- 本文の構成はモードのテンプレートと同じ。

## 既存ファイルがある場合

保存先に同名のファイルがあれば、新規作成ではなく更新として扱う。

- 既存の本文とタグを読み込んだうえで、変更したい点を中心に聞く。
- 変更を求められていない箇所は残す。
- ファイル名が違っても、同じフォルダ内に同じタイトルのファイルがあれば、更新するか新規作成するかを確認する。

## アプリでの確認

報告に含まれるURLを開く。

```
http://localhost:3000/docs/<ドキュメントID>
```

ドキュメントIDは `docs/` からの相対パス(拡張子なし)。日本語は URL エンコードされる。
開発サーバーは `npm run dev` で起動する。

## 補足

- 回答が決まっていない項目は、推測で埋めず「7. 未決事項」に入れる。未決事項は分野ごとに、現状と決める内容を表にまとめる。
- 機能要件は機能単位に分けて `F-01` から採番する。複数システムの場合は、先にシステム概要の表を置く。
- 非機能要件は `N-01` から採番し、`ID | 分類 | 項目 | 要件 | 備考` の表にする。
- `DOCS_DIR` 環境変数を設定している場合は、そのディレクトリに保存する。

## ファイル構成

```
.claude/skills/create-design/
  SKILL.md     スキル本体(Claude への手順)
  README.md    このファイル
  templates/
    requirements.md       要件定義書のテンプレート
    functional-design.md  機能設計書のテンプレート
```
